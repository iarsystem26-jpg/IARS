# IARS UI Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Repair and standardize every existing IARS screen so dashboards, forms, modal panels, navigation, and data views remain branded, accessible, and usable from 320-pixel mobile screens through desktop.

**Architecture:** Add a small set of presentation primitives for page shells and dialogs, strengthen the existing global design tokens, and migrate each route to those conventions without changing business logic. Work is grouped into independently reviewable route families, with unit coverage for shared interactive behavior and build/static audits for the full application.

**Tech Stack:** React 19, TypeScript 5.8, Vite 6, Tailwind CDN utilities, Lucide React, Vitest, Testing Library, jsdom

## Global Constraints

- Preserve the RMC/IARS blue, gold, green, slate, and white palette, current seal, IARS naming, Nunito, and Outfit.
- Do not change Firebase integration, mock-backend behavior, role permissions, navigation destinations, data schemas, or domain wording unless a UI defect blocks an existing workflow.
- Support viewport widths from 320 pixels through desktop without unintended full-page horizontal overflow.
- Keep administrative screens information-rich and student-facing screens focused.
- Do not add a large third-party component library.
- Keep light and dark themes behaviorally and visually equivalent.
- Use 44-by-44-pixel primary touch targets wherever practical, visible keyboard focus, dialog semantics, and reduced-motion support.

---

## File Structure

- `index.css`: global tokens, layout utilities, focus styles, scroll locking, reduced motion, and reusable semantic utility classes.
- `index.html`: single source for font loading and Tailwind theme configuration; remove duplicate inline presentation rules.
- `components/ui/Page.tsx`: shared page container, page header, section surface, and metric-card primitives.
- `components/ui/Modal.tsx`: accessible responsive modal shell, keyboard handling, focus restoration, scroll locking, and panel regions.
- `components/ui/Button.tsx`: consistent button sizing, variants, focus, disabled, and loading behavior.
- `components/ui/Layout.tsx`: responsive application shell and navigation behavior.
- `tests/setup.ts`, `components/ui/*.test.tsx`: jsdom setup and focused interaction tests for shared primitives.
- `views/*.tsx`: retain feature behavior while adopting consistent layout, responsive controls, modal shell, and mobile data presentation.
